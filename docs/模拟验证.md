# 模拟验证结论（2026-10-16）

> 目的：不下单任何硬件，验证需求 v1 的方案能不能做成。
> 结论：**软件这一侧全部跑通**，过程中发现并修掉了 3 个上了真机才会暴露的问题。剩下的风险全在物理层，只能拿到实物才能确认。

## 怎么验证的

| 层 | 跑的是什么 | 验证了什么 |
|---|---|---|
| 单元测试（18 个） | `firmware/lib/core` 业务代码 | 换日、星星、连续天数、休息日、没开机的日子、模板改动保留勾选、网页输入校验、断电恢复、深睡唤醒后局刷不留残影 |
| 电脑模拟器 | 同一份 core 代码 + SDL 窗口 + 本机 HTTP | 完整交互、界面效果、手机网页编辑；脚本 `test/sim/full_week.txt` 用虚拟时间从周五跑到下周一，16 张截图 + 每一步核对「屏上实际显示 = 固件以为的画面」 |
| Wokwi | **真机固件**（ESP32-S3 + GxEPD2 真驱动 + LittleFS + WiFi）+ 自写的 UC8179 屏幕仿真芯片 | 固件能在 ESP32-S3 上跑；屏幕驱动命令序列、全刷/局刷画面正确；连 WiFi、NTP 校时、编辑模式二维码；重启后状态还在 |

屏幕仿真（模拟器里的 `EpdEmu` 和 Wokwi 里的 `uc8179.chip.c`）都按控制器的真实语义模拟：old/new 两块 RAM、局刷只驱动有变化的像素、深睡后 RAM 丢失。漏写上一帧这类错误会直接以残留像素的形式显示出来（有反向测试证明它真能抓到）。

## 资源占用（真机固件）
- 程序 938KB / 3MB 分区；静态 RAM 14.7%
- 字库 + 图标 + 网页 1.8MB / LittleFS 4.9MB 分区
- 运行时 PSRAM 用约 2MB（字库），剩 6.3MB；内部堆剩 290KB

## 模拟中发现并修掉的问题
1. **屏幕 DC 接错了引脚**：原方案把 DC 接在 D6（GPIO43），它是串口 TX，开机日志会打在上面。Wokwi 里屏幕收不到任何命令。已改为 DC 接 D9、蜂鸣器接 D6，`hardware.md` 已更新。（2026-10-16 后来去掉了蜂鸣器，D6 现在空着。）
2. **刷屏时按键会丢**：刷新期间固件在等屏幕，孩子按快了第二下会被吃掉。已改为按键中断锁存。
3. **从没配过 WiFi 时读配置出错**，导致直接进入「时间未同步」页。已修。
4. 界面：删除线会把「口」划成「日」，已完成的任务改为整行变灰；`▼`、`·` 不在 GB2312 里，字库已补上。

## 模拟器验证不了的（要等实物）
| 项 | 风险 | 怎么兜底 |
|---|---|---|
| 真实刷新速度、残影、闪屏 | 低 | GxEPD2 对这块屏有实测数据；每 20 次局刷插一次全刷 |
| 按键唤醒（ext1）| 低 | Wokwi 不模拟 S3 真深睡（直接复位），逻辑在模拟器和单元测试里覆盖了；ESP-IDF 标准功能 |
| 续航、深睡电流 | 中 | 理论估算一个月以上；到货后用 USB 电流表实测 |
| 深睡时内部时钟漂移 | 中 | 每天 4 点联网校时 |
| 相框尺寸、按键手感 | — | 屏幕到货量过再买相框 |
| DESPI-C02 转接板兼容性 | 低 | 和 GDEY075T7 是同一厂家的配套件 |
